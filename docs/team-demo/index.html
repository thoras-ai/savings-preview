3. This is the whole user experience. One line to install, one line to run. It uses the kubectl logins they already have, so there's no setup and no license key. It finds whatever metrics they already collect: almost everyone has Prometheus.

Method

How it works

Their login

The kubeconfig contexts they already use

Their history

Up to 14 days of requests and usage per workload

The target

1.1 × the peak in each 15-minute window

The report

Savings, priced from Thoras's own node tables

Waste is every request above the target. Same simple rule as the forecaster: pay for what you use, plus a buffer.

Savings preview · team demo

4. Under the hood it's deliberately simple. Ricky's guidance: take what they use and add the buffer. We read their history, set each workload's target to 1.1 times its peak in any 15-minute window, and count everything requested above that as waste. Node prices come from the same price tables the product uses.

What it touches

What it reads and writes

Reads

  • Services, to find a metrics store
  • Prometheus queries through the API server proxy (GET only)
  • Pods, workloads, nodes and metrics-server, when there's no store
  • Datadog's query API, when given keys

Never

  • Installs anything in the cluster
  • Creates, changes or deletes a resource
  • Uploads data anywhere
  • Asks for credentials it doesn't already have

savings-preview check shows what it can read and from where, without pulling any history.

Savings preview · team demo

5. This matters for running it on a prospect's call. It only reads, through their existing kubectl access. Nothing is installed or changed, and the data stays on the laptop. The access list is in docs/security.md and deploy/rbac if anyone needs a scoped service account.

Getting results back

Getting results back from a customer

They run

savings-preview --all-contexts --collect-only

They send

savings-preview.zip: the report plus each cluster's data, a few MB

We open

report.html directly, or drop the zip on the upload page

Before reading anything, run prints what it found and what it will do, and waits for Enter.

Savings preview · team demo · --collect-only and the prompt land in v0.2.2

10. --collect-only skips the browser and server and exits, telling them what to send. The plan-and-confirm prompt shows exactly what it detected and what it will read before it does anything. Both are in review now and ship in v0.2.2.
